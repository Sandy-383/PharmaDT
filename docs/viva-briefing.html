02 The ninety-second answer

If you are asked "what did you build?", this is the shape of the reply.

A pharmaceutical supply chain simulated as a digital twin — twelve nodes, five drugs, 365 days — with five autonomous agents managing inventory, demand forecasting, expiry redistribution, vehicle routing, and anomaly detection. Every physical handoff is written to a cryptographic provenance ledger: hash-chained, ECDSA-signed, append-only enforced by database triggers. Demand forecasting is federated, so raw data never leaves a client.

The system reduces stockouts by 88.7% and wastage by 35.9% against a fixed-threshold baseline, measured over ten random seeds. Under four crisis scenarios it cuts unmet demand by 61.9%. The ledger raises counterfeit detection recall from 0.619 to 0.976, because forged batch identity is invisible to the machine-learning models by construction.

04 Questions you will be asked

Ordered by how likely they are. The answers are short on purpose — say the short version, then stop and let them follow up.

Your title says blockchain. This is a Postgres table.

It is a permissioned hash-chained ledger, and the substitution is deliberate. In a single-consortium simulated supply chain there are no mutually distrusting, independently operated validators, so Byzantine consensus is over-provisioned for the threat model. We keep the properties that matter — tamper-evidence via SHA-256 chaining, non-repudiation via per-node ECDSA P-256 signatures, write authorisation via a public-key allow-list, immutability via database triggers — and drop only distributed consensus. Access goes through an abstract ProvenanceLedger interface, so a Hyperledger Fabric backend would need no change to the agent layer.

Prove the ledger is actually tamper-evident.

make tamper-demo. It edits a record mid-chain, not at the tip — editing the last record breaks only its own hash, whereas seq 13,614 of 26,737 must also orphan everything after it. verify_chain() returns False and names the exact seq, then the demo restores the record and re-verifies. Note it first has to DISABLE TRIGGER to make the edit at all: the triggers prevent, the chain detects, and they are independent controls.

Why is your anomaly detection accuracy only 91%?

Because accuracy is the wrong metric and we report it only to show that. Anomalies are 5% of shipments, so a detector that flags nothing scores 95% accuracy and catches zero counterfeits. We report precision, recall, F1 and ROC-AUC. The number that matters is recall rising from 0.619 to 0.976 when the ledger check joins the ML screening.

Rossmann is retail sales data. This is a pharmacy.

Correct, and we state it as a validity threat rather than waiting to be asked. We take only the shape of each series — dispersion, weekday effect, seasonality — and rescale the level to the twin's own demand parameter. The magnitude does not transfer and we do not claim it does. The prescribed mitigation is validating against CMS Part D drug-level utilisation; data.cms.gov returns HTTP 403 to scripted clients, so that extract is not in place and the threat is open, not closed.

The guide specifies z = 1.65 for safety stock. You used 0.84.

We tested 1.65 and it was dominated. Over five seeds, z = 0.84 gives the same stockout reduction with an eighth of the wastage and half the extra inventory. Once the risk period is specified correctly the order-up-to level already carries most of the buffer, so additional safety stock mostly sits until it expires. make frontier traces the whole service-level curve; the table is in config.py next to the constant.

Why does your Merkle tree differ from Bitcoin's?

It follows RFC 6962, the Certificate Transparency construction. Bitcoin duplicates the final leaf when a level has an odd node count, which lets distinct leaf sets produce the same root — CVE-2012-2459. RFC 6962 splits at the largest power of two and domain-separates leaves (0x00) from internal nodes (0x01). There is a test that the collision case is not collidable.

Differential privacy destroyed your model. Isn't that a failure?

It is a real result with a structural cause. Five clients all participate every round, so the sampling rate is 1.0 and there is no privacy amplification by subsampling. Noise calibrated for that regime swamps a 52,000-parameter model. A deployment with hundreds of pharmacies and partial participation sits elsewhere on the curve. We report the cliff and explain it rather than presenting it as inherent.

Why is there no reinforcement learning? Your proposal mentioned MADDPG.

It was cut on the implementation guide's own risk assessment, which rates it highest risk and states that the Stage 6–10 heuristics ship the project. The prescribed trigger is to freeze it and report the omission rather than submit a rushed negative result. Every agent it would have replaced is working and measured.

How do you know the agents actually help, rather than just being present?

Every stage was measured against a control before it was believed. The ablation matrix adds one component per row over ten seeds with standard deviations, so each line shows what that component bought. Twice this caught an agent that was worse than the baseline — see the next section.

05 The three bugs — your strongest material

Three times an agent was measurably worse than the naive baseline it was meant to beat, and each was caught only because the measurement existed before the belief. If you get one open-ended "what did you learn?" question, answer with this.

Stage 6 — the reorder point was 363% worse than doing nothing clever

We used the last hop's transit time as the lead time. For a one-day leg that gave a reorder point of ~56 units against the baseline's 120, so the agent reordered later than the policy it was replacing. The fix is conceptual, not a tuned constant: in a multi-tier chain an upstream tier only reorders when its own position dips, so a pharmacy's stock is exposed for the cumulative echelon lead time (3 transit days through manufacturer → warehouse → distributor → pharmacy), not its final leg. Adding the one-day review interval gives a risk period of 4 — which is exactly where an independent sweep first reaches zero stockouts. Theory and measurement agreeing separately is what makes it defensible rather than curve-fitting.

Stage 7 — we accidentally built a bullwhip amplifier

Adding the Demand Agent raised inventory 68% and multiplied wastage 700×. The measured cause: forecast-to-history ratio was 1.00 at pharmacies but 2.26 (peaking at 4.00) upstream. Upstream "demand" is not consumer demand — it is the order flow the Inventory Agent itself generates, arriving in lumpy bursts. A moving average lands on a burst, doubles the estimate, and feeds it back into the policy that produced it. Scoping the forecaster to consumer-facing nodes removes the loop.

Stage 8 — redistribution that relocated waste instead of preventing it

The first version reduced wastage by 4%, not 88%. Three corrections, each from a measurement: candidate buyers must include downstream nodes (all the wastage sat at nodes with no same-tier peers); the action horizon must be longer than the FR-04 detection threshold, because at 30 days the receiving node cannot sell it either; and buyers must net off stock they already hold, or every node claims it can absorb the whole lot.

06 Say these before you are asked

Volunteering a limitation is far stronger than conceding one. Each of these is already in the README.

Limitation

The agents do not absorb the pandemic surge. Peak stockout stays at 54% against 91% for the baseline. No inventory policy can meet 10× demand for 60 days against finite manufacturing output. The agents manage scarcity; they do not create supply. The other three scenarios are absorbed completely.

Open threat to validity

CMS validation is not done. Rossmann's retail origin is mitigated by taking only temporal shape, but the drug-level cross-check the guide prescribes has not been run because the data source blocks scripted access. The loader is written and will pick the file up if it is placed in data/raw/cms/.

Topology finding, not a defect

A single-customer distributor branch is a redistribution dead end. NODE-DC-03 → NODE-PH-05 has nowhere lateral to send near-expiry stock. This surfaced from the Stage 8 diagnosis and is a network-design recommendation, not a bug. Similarly, the single manufacturer makes the factory-shutdown scenario the harshest possible version of itself.

Scope

Stage 14, the dashboard, is not built. It is presentation over an API that does not exist yet. Every number claimed is reproducible from the command line without it — which is the more important property.

The route and anomaly rows in the ablation matrix are identical to the expiry row on simulation KPIs. That is correct: the Route Agent's plan is advisory because shipment timing comes from the network's transit days, and the Anomaly Agent detects without altering stock flow. Their value is in the delivery-cost column and the detection metrics.
